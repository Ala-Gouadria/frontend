NORA FRONTEND PROJECT DOCUMENTATION
===================================

Project Summary
---------------
This is a React + Vite frontend for the Nora AI business dashboard.
The application includes authentication screens, setup/onboarding, an
interactive intelligence map, AI chat/workspace tools, reports, integrations,
assets, notifications, activity log, settings, and analytics card previews.

The project currently uses mock frontend API modules for most data flows.
These mock APIs simulate asynchronous requests with delays and return static
or in-memory data.


Technology Stack
----------------
- React 19
- React DOM 19
- Vite 8
- Tailwind CSS 4
- ESLint 9
- react-zoom-pan-pinch for the interactive map/zoom canvas


Main Commands
-------------
Run development server:
  npm run dev

Build production files:
  npm run build

Run lint checks:
  npm run lint

Preview production build:
  npm run preview


Main Entry Points
-----------------
src/main.jsx
  React root entry point. It imports global styles and renders App.

src/app/App.jsx
  Main application controller. It does not use React Router. Instead, it uses
  local React state and localStorage flags to decide which page/view to show.

src/styles/index.css
  Global styles, Tailwind import, body/root sizing, base font settings.


Application State and Navigation
--------------------------------
The app stores these localStorage keys:

nora:isAuthenticated
  Stores whether the user has entered the app.

nora:setupComplete
  Stores whether setup/onboarding is complete.

nora:view
  Stores the last selected app view after setup.

Important Components
--------------------
App
  Controls top-level view switching and localStorage state.

IntelligenceMap
  Main interactive workspace/map view. Uses zoom/pan behavior and opens panels
  such as Nora workspace and task overview.

  Task overview panel. Uses weekTaskApi, TaskHistoryLineChart,
  TaskAcceptanceBars, and PillButton.

PillButton
  Reusable gradient pill button with dotted arrow pattern. It supports
  accepted/decline/primary variants and compact mode.

  AI chat/workspace experience using noraWorkspaceApi mock conversation data.

  Primary app navigation icons and navigation callbacks.

Styling Notes
-------------
- The project uses many component-level CSS files.
- Some feature components use CSS modules.
- Tailwind is imported globally, but much of the UI is still custom CSS.
- The visual design relies heavily on gradients, soft shadows, blur effects,
  rounded panels, dotted chart elements, and image assets.
- The intelligence map uses fixed/floating panels and must be tested at the
  target browser viewport because Windows/browser scaling affects perceived
  sizes.


Current Development Options
---------------------------
Option 1: Keep the current manual view system
  Simple and already working. Good for fast iteration. The downside is that
  deep links and browser back/forward behavior are limited.

Option 2: Move to React Router
  Better for real product navigation, URL sharing, browser history, and route
  guards. This is recommended before production if the app grows.

Option 3: Keep mock APIs during UI development
  Good while finishing design. Replace the mock API modules later with real
  HTTP calls while keeping the same function names where possible.

Option 4: Add a real backend integration layer
  Create a shared API client for authentication, workspace data, tasks,
  integrations, reports, assets, and notifications.

Option 5: Split large bundles
  The production build warns that the main JavaScript chunk is large.
  Dynamic imports/code splitting for pages and heavy card previews would
  improve load time.

Option 6: Consolidate duplicate card systems
  There are card components under both src/components/Cards and src/features.
  Choose one structure long-term to reduce duplicate styling and maintenance.

Option 7: Create a design system
  Promote repeated elements such as PillButton, chart cards, tabs, badges,
  panels, and icon controls into a consistent component library.


Recommended Next Improvements
-----------------------------
1. Add React Router or another routing layer.
2. Replace localStorage-only auth with a real auth/session flow.
3. Connect API modules to backend endpoints.
4. Add responsive viewport testing for the intelligence map and panels.
5. Add code splitting for pages and analytics card previews.
6. Normalize naming and casing, for example restPassword vs ResetPassword.
7. Reduce duplicate card implementations between components and features.
8. Add unit/component tests for critical shared UI components.
9. Add visual regression screenshots for WeekTask, PillButton, and map panels.
10. Document design tokens for colors, shadows, spacing, and typography.
